🔁 LLM Eval CI/CD Pipeline — Complete Flow

What happens from a code change to production deployment
① SETUP PHASE — Done Once
📋
Build the Golden Dataset
Create a JSON/CSV file with 100+ test questions, expected answers, source documents, and edge cases. This is your permanent test suite — your ground truth.
100+ Q&A pairs Expected answers Edge cases Stored in GitHub
🤖
Build the LLM / RAG Pipeline
Your actual AI system — LLM + vector database + retrieval logic + system prompt. This is the thing you are testing and evaluating.
LangChain ChromaDB / Pinecone OpenAI / Anthropic API System Prompt
⚙️
Configure GitHub Actions (CI/CD Trigger)
Write a YAML file in your repo that tells GitHub: "Every time someone pushes code, automatically run the evaluation pipeline."
.github/workflows/eval.yml Triggers on git push Runs in cloud automatically
② TRIGGER PHASE — Every Time Something Changes
✏️
Developer Makes a Change
Could be any of: editing the system prompt, swapping the model, updating the RAG knowledge base, or changing retrieval logic.
Prompt change Model swap RAG DB update Retrieval logic edit
git push
🚀
GitHub Actions Automatically Fires
No manual action needed. GitHub detects the push and immediately spins up the evaluation pipeline in the cloud.
Automatic No human needed Runs in seconds
③ EVALUATION PHASE — The Core Engine
📂
Load Golden Dataset
Pipeline reads all 100+ test questions from the golden dataset JSON file stored in the repo.
Read test_cases.json Load expected answers
🔁
Run All Questions Through the LLM Pipeline
Each of the 100+ questions is sent through your actual LLM/RAG system. Records actual answers, retrieved documents, and latency for each.
Query LLM for each question Record actual answers Track latency per call Track token cost
🔬
Score Every Answer with RAGAS / DeepEval
The evaluation library scores each answer across multiple dimensions using LLM-as-judge and semantic similarity.
Hallucination Rate Answer Relevance Faithfulness to Sources Context Precision
📊
Compute Aggregate Metrics
Calculate final numbers across all 100+ test cases: average scores, percentile latency, total cost.
Hallucination: 3.2% Relevance: 0.81 p95 Latency: 2.1s Cost: $0.014/query
④ QUALITY GATE PHASE — Pass or Fail
🎯
Compare Against Thresholds
Each metric is checked against pre-defined quality gates in your config file.
Hallucination < 5% Relevance > 0.75 p95 Latency < 3s Cost < $0.02
All Quality Gates Pass?
✅ YES — ALL PASS
🟢
Deployment Approved
GitHub marks the check as passed. The pull request can be merged. Change goes to production safely.
PR approved Merge allowed Deploy to prod
❌ NO — GATE FAILED
🔴
Deployment Blocked
GitHub blocks the merge automatically. Developer gets a detailed failure report showing exactly which metric failed and by how much.
PR blocked Merge prevented Alert sent
⑤ MONITORING PHASE — Always Running
💾
Save Results to Database
Every evaluation run — pass or fail — is stored with a timestamp, commit ID, and all metric scores. This builds your history over time.
SQLite / Supabase Timestamp + Commit ID All metric scores saved
📈
Dashboard — Track Trends Over Time
A visual dashboard shows how your AI system quality evolves across every change ever made. Compare prompt versions, model versions, and spot regressions instantly.
Streamlit / React Metric trends Best prompt version Cost history Regression alerts
